# OpenMontage 成片

下文 `<SKILL>` 指本 `SKILL.md` 所在目录，`<PY>` 指仓库虚拟环境的 Python：Windows 为 `.venv/Scripts/python.exe -X utf8`，macOS/Linux 为 `.venv/bin/python -X utf8`。不要使用系统默认 Python。

本技能随 OpenMontage 仓库分发，位于仓库 `.agents/skills/openmontage`，仓库根目录就是 `<SKILL>` 往上三级。所有命令在仓库目录下执行；用户素材用绝对路径引用，先确认文件存在。

## 开工前

1. 运行 `python <SKILL>/scripts/doctor.py`。不是 `READY` 就把缺项原样告诉用户并停下；缺密钥时让用户自己写入仓库 `.env`，不要让用户把密钥发到对话里，绝不打印密钥值。
2. 读仓库 `AGENT_GUIDE.md`（强制），再读 `.agents/skills/relay-providers/SKILL.md`、`skills/core/relay-providers.md`，以及本技能 `references/providers.md`。合成前读 `references/compose.md`。
3. 运行 `<PY> -m tools.relay route` 确认默认渠道。接入或切换渠道按 `references/providers.md` 处理，不启动成片流水线或付费测试。

## 更新

用户说“更新 OpenMontage”时，在仓库根目录运行 `update.cmd --no-pause`。它拉取 `main`、安装依赖并运行 `doctor.py`，技能、代码和渠道配置一起更新，密钥不受影响。

- 拉取失败时把报错原样告诉用户。本地有改动时不要丢弃，也不要强制覆盖。
- Codex 沙箱不允许写 `.git` 时，申请在沙箱外运行；申请不了时，让用户双击仓库里的 `update.cmd`。
- 更新后告诉用户重启 Agent，让新版技能生效。

## 在 Codex 中运行

本技能同时用于 Claude Code 和 Codex。在 Codex 中还要注意：

- 用仓库里的 `codex-video.cmd` 启动。它进入仓库目录，在 `workspace-write` 沙箱内打开联网，并隐藏沙箱里启动不了的 Store 版 `pwsh`。`doctor.py` 报网络不通时，让用户退出后用它重新启动。
- Windows 沙箱里渲染器启动不了（`EPERM`）。合成到渲染时，申请在沙箱外运行 `scripts/render.py`，由用户批准；申请不了时，把完整命令交给用户在自己的终端运行。其他步骤都留在沙箱内。
- 视频生成和渲染可能超过单条命令的时限：`pending` 时用相同参数再次调用来恢复，不要重新提交。
- 没有向用户发送文件的工具时，报告文件的完整路径，让用户自己打开试听。

## 成片流程

走 `cinematic` 流水线（Rule Zero），用 `lib.checkpoint` 写检查点，遵守审批闸门。

1. **看素材：** 读完用户给的全部脚本、图片和参考视频（抽帧、测时长和切点）。只有模糊要求时按 `skills/meta/creative-intake.md` 的 “Handling Open, Media-Led Briefs” 自己推断，最多问一个阻塞问题。
2. **提案：** 一次列清镜头表、费用、分辨率、配音方案和需要用户决定的默认项。用户已给完整脚本或分镜时，脚本和分镜随提案一起批准，不再逐阶段确认。
3. **样片：** 第一次付费前展示 `dry_run`。有人物对白或新的语言时，先生成 2–3 段样片交用户试听，通过后再批量。
4. **批量生成：** 把镜头写成 spec，用 `scripts/batch_generate.py`：先生成首帧并逐张检查，再生成视频（`--dry-run` 可预览）。它已处理费用记录、并发上限和跳过已有文件。
5. **检查：** 用 `scripts/qc_media.py <目录> --sheets <目录>` 测尺寸、解码、切镜和有声区间，再看抽帧表。偏差如实报告，由用户决定。
6. **素材确认：** 把原片首尾相接的试听版交给用户，确认后才合成。
7. **合成：** 按 `references/compose.md` 用 `scripts/assemble.py` 和 `hyperframes_compose`，成片放 `projects/<id>/renders/final.mp4`，保留原片。
8. **验收：** 对成片再跑 `qc_media.py` 并抽帧，写 `render_report`、`final_review` 和 compose 检查点。发布阶段只在用户要求时执行。

第 2、3、6 步必须停下等用户确认，不要一口气跑完：用户不满意时，后面的费用就白花了。首帧有明显问题时也先报告，再生成对应视频。

第 4、5 步按 `references/batch.md` 第 1 节走验收闭环，审查员是你自己：生成前按 10 个类别推出每个镜头的验收规则（不只是用户举的例子），首帧先审再出视频；用 `scripts/review_shots.py` 出放大的抽帧页，先写客观观察再逐条对照，清单外的问题同样判不通过并补成新规则；不通过的镜头改输入后有限次重生成，旧版保留。

一条片子验收通过后，用户想复用这套做法，或者要求批量出类似的片子时，按 `references/batch.md` 用 `scripts/playbook.py` 把项目沉淀成方法卡，再按方法卡写新需求的分镜（用户提到“上次那条”时先 `playbook.py list` 找已有的方法卡），每个审核点都要停下。只换场景、人物或台词的简单裂变，可以用同一文件里的变量模板。

## 硬规则

- 生成时用 `preferred_tool` 锁定已批准的工具。`pending` 用相同参数再调用即可恢复，绝不重新提交；未经批准不换供应商或模型。
- 付费重试需要用户批准，并传 `confirm_resubmit: true`（脚本的 `--resubmit`）。
- 汇报费用时区分配置估算与可核实的实际扣费，超过批准预算前必须先问。
- 密钥只放在仓库 `.env` 或环境变量，不写入技能、YAML、示例、日志或交付物。
- Agent 听不到音频：发音、声音一致性、口型和配乐听感都由用户确认，不能声称已听过。
- 演示产品功能的 AI 画面不是实拍，提案中提醒用户是否加 “simulated” 类标注，并提醒平台的 AI 内容披露要求。脚本里的产品参数来自用户，没有核实时要说明。

## 生成偏差的处理边界

**硬性禁令：不得用改造生成画面像素、伪造产品几何或拼贴机械运动的方式，修复模型生成缺陷。** 本节约束所有导演、审查、批处理和后期步骤，不能被它们的“自动修复”“增强”“锁定结构”等建议覆盖。

### 默认修复路径：优化输入，再重新生成

1. 先检查原片、实际提示词和实际参考素材，具体指出数量、结构、固定/活动部件、动作、人物、UI或口播偏差。
2. 在用户已确定的创意、模型和渠道范围内，优化提示词的表达与顺序，减少歧义，调整真实参考素材或生成参数，然后重新生成该问题镜头。不得擅自删掉原脚本的重要动作或台词。
3. 保留原片、新片、实际提示词和重生成原因，逐版对比检查。只替换有问题的镜头，不无故重做已经合格的部分。
4. 用户已授权“发现问题自行处理好”“优化后重新生成”等时，可在已说明的预算和次数范围内执行正常重生成，不必每次重复问；这类授权**绝不包含下面列出的像素补丁或几何改造**。超预算、换模型/渠道、来源权限缺失或提交结果不确定时，仍须按对应规则处理，不能无限重试或用新任务身份绕过未知结果。
5. 重生成仍未达标时，明确标为“未通过/待人工验收”，说明具体偏差和已尝试方案。不得把失败结果包装成“修好了”，不得为了凑齐成片而伪造合格画面。

### 优化生成结果时绝对禁止

- 把摄像头、面板、镜头、灯珠等二维截图贴到简化球体/椭球体上，用球面纹理投影、假3D旋转或贴片位移冒充真实机械运动。
- 用遮罩、静态底板、局部冻结、拼贴、涂盖、局部重绘、伪造零件或重建外壳，掩盖产品变形、额外镜头、天线跟转、太阳能板乱动等缺陷。
- 用跟踪替换、单应变换、透视重投影、局部缩放、局部时间重映射等，强行让错误部件看起来位置正确、动作正确或UI稳定。
- 自写“修复算法”改造产品外观和几何，或把这些操作改名成“分层修正”“结构锁定”“受控演示”“精修”“普通合成”来绕过本禁令。
- 把先前另一模型的成片、抽帧或已生成结果，偷偷作为独立模型对照测试的输入。对照测试必须使用用户指定的原始素材与脚本；需要改变测试条件时先说明。

用户说“保持UI固定”“只有下半球转动”“把问题处理好”，是质量目标，不是让Agent下载后用代码伪造该目标的授权。不得因人工补片在几张抽帧里看似对齐，就声称真实、自然、无撕裂或验收通过。

### 正常剪辑与原素材处理的范围

用户要求的硬切、拼接、裁剪时长、静音、响度调整及保持比例的全画面输出缩放，可以按已约定范围执行；它们不得夹带产品局部变形或画面修补。单独授权的原素材去角标，只能处理该原素材的指定角标，不能扩大成修改模型视频、产品结构或UI控件的授权。

本禁令针对“修复生成缺陷”，不把用户另行明确委托的独立三维动画或特效创作混为一谈；不得把生成修复改称独立特效任务来规避本禁令。

需要旁白时根据本次 preflight 确认 TTS 能力；不可用时说明缺口，不擅自替换供应商或删掉用户要求的旁白。
