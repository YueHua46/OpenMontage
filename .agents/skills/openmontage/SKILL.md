# OpenMontage 成片

下文 `<SKILL>` 指本 `SKILL.md` 所在目录，`<PY>` 指仓库虚拟环境的 Python：Windows 为 `.venv/Scripts/python.exe -X utf8`，macOS/Linux 为 `.venv/bin/python -X utf8`。不要使用系统默认 Python。

本技能随 OpenMontage 仓库分发，位于仓库 `.agents/skills/openmontage`。用户级入口（`~/.agents/skills/openmontage`、`~/.claude/skills/openmontage` 等）指向这个目录：要改技能只改仓库里的，不要在用户目录另放独立副本。经链接打开本文件时，不能从链接位置往上推算仓库；以 `doctor.py` 第一行 `OpenMontage repo:` 打印的路径为仓库根目录（它会解析链接，也认 `OPENMONTAGE_HOME`）。所有命令在仓库目录下执行；用户素材用绝对路径引用，先确认文件存在。

本技能的脚本（`batch_generate.py`、`review_shots.py`、`qc_media.py`、`preview.py`、`playbook.py`、`app_feed.py` 等）都在 `.agents/skills/openmontage/scripts/`。仓库根目录的 `scripts/` 是另一组无关脚本，在那里找不到它们不代表脚本不存在。

## 开工前

1. 运行 `python <SKILL>/scripts/doctor.py`。缺 Python 包（Pillow、numpy、faster-whisper 等）或 ffmpeg、Node.js、git 时，直接运行 `doctor.py --fix` 安装，装完再检查，环境要齐全，不要因为缺依赖就跳过审片或切分步骤。只有缺密钥时才停下：让用户自己写入仓库 `.env`，不要让用户把密钥发到对话里，绝不打印密钥值。在 Codex 沙箱里装不上时，申请在沙箱外运行。
2. 读仓库 `AGENT_GUIDE.md`（强制），再读 `.agents/skills/relay-providers/SKILL.md`、`skills/core/relay-providers.md`，以及本技能 `references/providers.md`。写提案和提示词前：
   - 读 `references/failure-modes.md`；
   - 按画面观感从 `references/styles/` 选风格模板；
   - **按商品类型查 `references/categories/README.md`**：命中已有品类（例如安防监控摄像头读 `references/categories/security-camera.md`）时，完整加载该品类的结构、尺度、视角与拍法规范；做其他尚无专属文件的品类时，直接按通用物理与尺度规则执行，不硬套无关品类。
   - 合成前读 `references/compose.md`。
3. 运行 `<PY> -m tools.relay route` 确认默认渠道。接入或切换渠道按 `references/providers.md` 处理，不启动成片流水线或付费测试。

## 更新

用户说“更新 OpenMontage”时，在仓库根目录运行 `update.cmd --no-pause`。它拉取 `main`、安装依赖并运行 `doctor.py`，技能、代码和渠道配置一起更新，密钥不受影响。

- 拉取失败时把报错原样告诉用户。本地有改动时不要丢弃，也不要强制覆盖。
- Codex 沙箱不允许写 `.git` 时，申请在沙箱外运行；申请不了时，让用户双击仓库里的 `update.cmd`。
- 更新后告诉用户重启 Agent，让新版技能生效。

## 在 Codex 中运行

本技能同时用于 Claude Code、Codex 和 Antigravity。在 Codex 中还要注意：

- 用仓库里的 `codex-video.cmd` 启动。它进入仓库目录，在 `workspace-write` 沙箱内打开联网，并隐藏沙箱里启动不了的 Store 版 `pwsh`。`doctor.py` 报网络不通时，让用户退出后用它重新启动。
- Windows 沙箱里渲染器启动不了（`EPERM`）。合成到渲染时，申请在沙箱外运行 `scripts/render.py`，由用户批准；申请不了时，把完整命令交给用户在自己的终端运行。其他步骤都留在沙箱内。
- 视频生成和渲染可能超过单条命令的时限：`pending` 时用相同参数再次调用来恢复，不要重新提交。
- 没有向用户发送文件的工具时，报告文件的完整路径，让用户自己打开试听。

## 成片流程

走 `cinematic` 流水线（Rule Zero），用 `lib.checkpoint` 写检查点，遵守审批闸门。

1. **看素材：** 读完用户给的全部脚本、图片和参考视频（抽帧、测时长和切点）。图片和视频帧先用 `scripts/preview.py` 转成小图再看（见下文“看图”）。只有模糊要求时按 `skills/meta/creative-intake.md` 的 “Handling Open, Media-Led Briefs” 自己推断，最多问一个阻塞问题。
2. **提案：** 一次列清镜头表、费用、分辨率、配音方案、选用的风格模板（`styles/`）与产品品类指南（`categories/`，若有），以及需要用户决定的默认项。用户已给完整脚本或分镜时，脚本和分镜随提案一起批准，不再逐阶段确认。带货、转化广告默认按 `references/batch.md` 1.0 的“钩子 → 痛点 → 方案 → 证明 → 下单引导”结构写，用户另有结构时按用户的；没有合适模板就按用户描述写，不硬套。
3. **样片：** 第一次付费前展示 `dry_run`。没有方法卡、又有人物对白或新的语言时，先生成 2–3 段样片（优先测红/黄高风险镜头），由 Agent 完成逐帧审查、ASR 台词核对及可用的音轨检查，再交用户预览。默认确认后再批量；用户已明确委托 Agent 自主初审、声音意见后续再反馈时，按该委托继续已授权范围内的制作，不重复要求用户承担常规审片或把音色偏好确认作为停工条件。该委托不扩大付费预算、重试次数或模型/渠道授权。按已就绪的方法卡批量时不单做样片，所有条目同步推进（`references/batch.md` 3.1）。
4. **批量生成：** 把镜头写成 spec，用 `scripts/batch_generate.py`：先生成首帧并逐张检查，再生成视频（`--dry-run` 可预览）。它已处理费用记录、并发提交和跳过已有文件；多条片子用 `--project v1 v2 v3` 一次并发跑完。
5. **检查：** 用 `scripts/qc_media.py <目录> --sheets <目录>` 测尺寸、解码、切镜和有声区间，再看抽帧表；用 ASR 核对台词，异常片段先自行分段复核。偏差如实报告，在已有授权和预算内处理，不把 Agent 可完成的检查交还用户。
6. **素材确认：** 把原片首尾相接的试听版交给用户；默认确认后才合成。用户已明确委托 Agent 自主审片并合成时，完成客观检查、保留异常记录后按委托推进，不因用户尚未试听音色而停工；无授权的付费生成仍不能执行。
7. **合成：** 按 `references/compose.md` 用 `scripts/assemble.py` 和 `hyperframes_compose`，成片放 `projects/<id>/renders/final.mp4`，保留原片。
8. **验收：** 对成片再跑 `qc_media.py` 并抽帧，做整片 ASR 复核，写 `render_report`、`final_review` 和 compose 检查点。发布阶段只在用户要求时执行。

第 2 步的创意和费用授权必须落实；第 3、6 步默认等待用户确认，但用户已明确委托 Agent 自主验收或表示声音问题以后反馈时，以该委托为准，不重复索取同一确认。保留原片和真实审查结论，不能用委托掩盖缺陷或扩大预算。首帧有明显问题时先报告，在已有授权内修正后再生成对应视频。

第 4、5 步按 `references/batch.md` 第 1 节走验收闭环，审查员是你自己：同一人物或场景出现在多个镜头时，先出参考图（`"kind": "reference"`）并经用户确认，分镜用 `@id` 引用它（`references/batch.md` 1.15）；生成前按 12 个类别（含跨镜连贯 `continuity`、符合风格模板的观感 `realism` 及所选品类专属约束）推出每个镜头的验收规则，首帧先审再出视频；用 `scripts/review_shots.py` 出放大的抽帧页，先写客观观察再逐条对照，清单外的问题同样判不通过并补成新规则；不通过的镜头改输入后有限次重生成，旧版保留。首帧是镜头动作的起点，不是动作的结果（`references/batch.md` 1.1）；视频提示词按 1.16 写，让动作按真实速度发生。

**写提示词之前，先按 `references/batch.md` 1.05 给每个镜头分级（绿/黄/红）。** 红色镜头（跑步、急转身、听到声音后反应、多人走位、产品局部机械运动、动态屏幕界面、穿越运镜等）保留剧情和台词，改成模型做得像的拍法或用真实素材，提案里逐镜说明并由用户确认；不要把模型做不好的动作直接交给它反复盲抽。

**经验按层当轮沉淀，不堆成流水账：** 写首帧和视频提示词前对照 `references/failure-modes.md`（及命中品类的故障表）。用户指出的问题或你自己发现的新问题，当轮提炼原因、预防和发现方法并告诉用户补在哪里（**不写具体项目代号或 take 流水账，不在主 `SKILL.md` 堆砌个案**）：
- 跨品类通用的图像/动作/审片/合成问题 → 以四列表格行补进 `references/failure-modes.md`；
- 只属于某种画面观感风格的问题 → 补进 `references/styles/` 对应文件；
- 只属于某类商品物理结构或功能演示的问题 → 抽象到品类级补进 `references/categories/` 对应文件；
- 能用脚本自动拦截的规则 → 同步补进检查脚本（如 `voice_check.py`、`review_shots.py`）。

**付费生成只走 `batch_generate.py`，重生成只走 `review_shots.py retake` + `batch_generate.py --only`。** 不要用 `registry.get(...).execute()`、`python -c` 或自写脚本直接调生成工具：那样不进 `cost_log.json`，绕开预算、重生成次数和首帧闸门，版本命名也和 `review.json` 对不上。直接调工具只用于 `dry_run` 查看请求。预算或次数不够时，先问用户，再改 spec 的 `budget_usd` / `max_retakes`。用户授权“有问题自己重做”，同样走这条路径。多个镜头要重做时一起 `retake`，再用一次 `--only a b c` 并发提交，不要一张一张串行跑。

### 原稿、物理与身份输入检查

- **锁定原稿结构与时长：** 用户要求优化生成缺陷时，先锁定原稿镜数、顺序、台词、关键动作和目标时长范围；风格模板与品类拍法调整不能覆盖这些要求，不得靠删减剧情或缩短片子来规避生成难点。
- **开放式物理与参照系检查：** 物理与常识检查适用于所有物体和动作，不以已知故障清单为边界。生成前按 `references/batch.md` 1.12 建立本镜的物体、连接、支撑、可动自由度和起止状态，分清外部机位、被拍商品与安装物、镜/屏内视角与 UI 层；审查时跟踪完整过程的相对位置与尺度（6fps 抽帧不是连续播放，动作时段逐帧看“正常速度看一眼像不像”）。相同首尾帧只是返回起点的约束，不能当外观锁定器（批处理会拦截无依据的相同尾帧）；不同首尾帧正确也不能抵消中间过程的超调、跳变或违反常理。
- **单一身份与体型母版：** 对照已确认人物参考，连用户原始分镜首帧的脸、年龄、胡须、领口、发型和服装也要先核对（原分镜也可能漂移）。重复角色只设一套有效母版，同时锁定脸型与完整躯干体型（肩宽、颈围、胸腰、四肢粗细和衣服松紧），并排比对所有出镜首帧（含坐姿、近景、夜景），人物不能忽胖忽瘦。细则见 `references/batch.md` 1.15。
- **商品同深度物理尺度：** 从真实尺寸资料锁定单位、测量范围和部件比例，以同一深度的安装物/桌面/手持参照核对首帧、视频全程及切镜处。镜头远近改变画幅占比，但不能改变商品与同一安装物的相对大小。通用方法见 `references/batch.md` 1.155，具体尺寸只写项目 spec，不写成通用常量。
- **核实实际生效的模型输入：** 记录**实际发送**的首帧、尾帧、独立参考图及渠道声明支持的输入模式。Agent 读过四视图、提示词写了“同一个人”、或 spec 列了未发送路径，都不等于模型收到了身份参考；缺少多图参考能力时如实说明。从虚焦远景推进到清晰近景时，需验证输入能否辨认身份或提供同机位合规尾帧，不得复制开场作尾帧取消运镜。
- **无人镜头隔离与系统性停损：** 无人环境、纯产品特写和屏幕界面镜头使用独立局部提示词，画外声明确写 `off-screen` 且镜内无人，不套用人物出镜模板。发现系统性换脸、陌生人入镜或关键动作丢失时，在 spec 设 `production_hold.active=true` 暂停同类付费批量，查明根因并修正有效输入后再解除，不能只加一句“保持一致”继续盲抽。

## 看图

Agent 宿主会把看过的每张图以 base64 留在对话历史里并在后续每次请求整段重发。原始 PNG 一张 2–3 MB，累积几十张就会超过网关上限报 `413 Payload Too Large`，对话直接中断。视觉模型本来就会缩到约 1280–2048 像素，大文件只增加字节，不增加细节。

- 只看脚本产出的 JPEG：首帧和视频用 `review_shots.py sheet` 打印的 `frame`、`page`、`zoom` 文件；其他图片或临时抽帧先运行 `<PY> <SKILL>/scripts/preview.py <文件或目录> [--times 0.5 2]`，再看它打印的路径。
- 不直接打开 `assets/images/*.png`、`assets/video/*.mp4` 或自己用 ffmpeg 抽出的 PNG；不用 `detail: "original"`。
- 看不清细节就在 spec 的 `regions` 里加放大区域，重新 `sheet --only <镜头>`（区域过多过小时加 `--region-pages` 分页），不要换成看原图。
- 同一张图不重复看；一次调用里看的图控制在 6 张以内。
- 一旦出现 413，告诉用户新开一个对话，从项目检查点和 `review_shots.py status` 接着做。

## 对话压缩或交接之后

长任务中途对话被压缩，或者换到新对话时，先恢复状态，不要凭摘要重新摸索：

1. 写交接摘要时必须包括：项目 id、spec 路径、本技能脚本目录 `.agents/skills/openmontage/scripts/`、选用的 `style` / `category`、各镜头当前 take 和审核结论、已用费用和剩余预算、用户的最新授权范围和创意修正。
2. 接手后重新读本文件，运行 `review_shots.py status --project <id> --spec projects/<id>/shots.json`，并读 `projects/<id>/cost_log.json`，以这两个磁盘文件为准接着走闭环；摘要与磁盘状态对不上时告诉用户。

一条片子验收通过后，用户想复用做法或批量裂变同类片子时，按 `references/batch.md` 第 2、3 节用 `scripts/playbook.py` 沉淀或应用方法卡（用户提到“上次那条”时先 `playbook.py list` 查找）；只换场景、人物或台词的简单裂变用 `plan_variants.py`。

## 硬规则

- 生成时用 `preferred_tool` 锁定已批准的工具。`pending` 用相同参数再调用即可恢复，绝不重新提交；未经批准不换供应商或模型。
- 付费重试需要用户批准，并传 `confirm_resubmit: true`（脚本的 `--resubmit`）。
- 汇报费用时区分配置估算与可核实的实际扣费，超过批准预算前必须先问。
- 密钥只放在仓库 `.env` 或环境变量，不写入技能、YAML、示例、日志或交付物。
- **音频检查与证据边界：** Agent 先用 Whisper/ASR 核对台词与时间、用 `qc_media.py` 查响度/峰值/有声区间，异常转写先分段复核并结合画面查口型。只有 ASR 与声学指标时必须说明证据边界，绝不声称“亲耳听过”，也不把音高接近或转写一致等同于音色自然。用户明确允许声音意见后续反馈时，不把未试听当成停工门槛，仅如实保留待人工试听项。
- **一人一音硬约束：** 旁白必须选定合适的声音锁进 `voice.reference_id`，整片及同系列固定使用，整段一次生成后用 `split_narration.py` 切分并跑 `voice_check.py`（需要旁白时先在 preflight 确认 TTS 能力，不可用时说明缺口）。镜头内人物说话（对白）同样必须一个角色固定一个声音，避免视频模型原声每镜换人；三种合规方案（锁角色声音模型 / 原声静音配固定 TTS 并避开口型特写 / 视频原声集中生成画外音再切分）及细则见 `references/compose.md`。
- **披露与卖点合规：** 默认不在画面上加 “Simulated”“Dramatization” 等 AI 标注小字，提醒用户发布时打开平台的 AI 内容标签（用户明确要求时才加进画面）。脚本里的产品参数和卖点（如“免订阅”“即时接通”“2K”“防水等级”）未经核实时在提案里逐条列出风险，由用户决定去留，不得擅自删改用户台词与卖点。

## 生成偏差的处理边界

**硬性禁令：不得用改造生成画面像素、伪造商品三维几何或局部拼贴运动的方式，修补模型生成缺陷。** 本节约束所有导演、审查、批处理和后期步骤，不能被任何“自动修复”“增强”“结构锁定”建议覆盖。

### 默认修复路径：优化输入，再重新生成

1. 先检查原片、实际提示词和实际参考素材，具体指出数量、结构、固定/可动部件、动作、人物、UI 或口播偏差。
2. 在用户已确定的创意、模型和渠道范围内，优化提示词表达与顺序、调整真实参考素材或生成参数，重新生成问题镜头；不得擅自删掉原脚本的重要动作或台词。
3. 保留原片、新片、实际提示词和重生成原因，逐版对比检查。只替换有问题的镜头，不无故重做已合格的部分。
4. 用户已授权“发现问题自行处理好”“优化后重新生成”时，可在已批准预算和次数内执行正常重生成，不必每次重复问；但**这类授权绝不包含下述像素补丁或几何伪造**。
5. 重生成次数用尽仍未达标时，明确标为“未通过/待人工验收”，说明具体偏差和已尝试方案，绝不把失败结果包装成“已修好”。

### 优化生成结果时绝对禁止

- 把商品平面截图、面板、部件或图标贴到简化三维几何体（如球体、椭球体、方盒）上，用纹理投影、假 3D 旋转或贴片位移冒充真实机械运动。
- 用遮罩、静态底板、局部冻结、拼贴、涂盖、局部重绘、伪造零件或重建外壳，掩盖商品变形、多出部件或固定结构乱动等缺陷。
- 用跟踪替换、单应变换、透视重投影、局部缩放、局部时间重映射等，强行让错误的生成部件看起来位置正确、动作正确或 UI 稳定。
- 自写“修复算法”改造生成商品的外观和几何，或将其改名成“分层修正”“结构锁定”“受控演示”“精修”“普通合成”来绕过禁令。
- 把先前另一模型的成片、抽帧或生成结果，偷偷作为独立模型对照测试的原始输入。

用户说“保持 UI 固定”“只有某部件转动”“把问题处理好”，是质量目标，不是允许用代码伪造画面的授权。

### 正常剪辑与合法后期的范围

- 用户约定的硬切、拼接、裁剪时长、静音、响度调整及保持比例的全画面输出缩放。
- **无视差宽画幅构图裁切与独立 UI 层合成：** 在无近远景视差的宽画幅固定机位画面上做匀速二维平移裁切（如模拟定轴摇镜构图），以及在合成阶段叠加独立的真实/标准 App 界面层、检测框和字幕（如 `app_feed.py`、`overlay.html`），属于合法后期构图与界面合成，不得夹带对生成商品本体的局部变形或遮盖修补。
- 单独授权的原素材去角标，仅限处理该原素材的指定角标，不能扩大到修改模型生成的商品结构或控件。独立委托的三维动画/特效创作与“修补生成缺陷”分开处理，不得借口规避本禁令。
