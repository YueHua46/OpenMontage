# 一份母版批量出多个版本

用途：人把提示词打磨成母版，Agent 按变量表生成多条版本。故事结构和卖点不变，场景、口播和人物不同。

## 分工

- **用户把控：** 母版提示词、卖点、台词方向、变量取值、每个审核点的决定。
- **Agent 负责：** 展开版本、检查重复和缺项、算费用、批量调用、合成、报告偏差。
- 产品结构、卖点顺序、功能描述和合规内容写进 `fixed` 或母版文字，不随版本变化。

## 流程和审核点

每个审核点都要停下等用户确认。只对用户选中的版本进入下一步，不要一口气跑完。

1. **版本表（免费）：** 写 `master.json`，运行 `scripts/plan_variants.py --master master.json`。把版本表、重复提醒和费用发给用户。有 `PROBLEM` 时先解决。
2. **关键首帧（每版只花几张图的钱）：** 用户确认后加 `--create`，再用 `batch_generate.py --project <name>-<vid> --spec projects/<name>-<vid>/shots.json --stage frames --only <关键镜头>`。给用户看，淘汰或调整版本。
3. **样片（每版 1–2 段）：** 只给通过的版本生成带台词的镜头，交用户试听。换语言、人物或声音时不能省略。
4. **其余素材：** 生成通过版本的其余首帧和视频，逐版用 `qc_media.py` 检查，把试听版交给用户。
5. **合成：** 用户确认后逐版按 `references/compose.md` 合成。可以先合成 1 条确认剪辑风格，其余再批量。

## 注意事项

- 同时提交的视频总数不超过 3 段，多个版本要排队，不要各开 3 路。
- 每个版本是独立项目，有自己的费用记录、原片和检查点。
- 费用按版本和批次分别批准，例如“5 条，每条不超过 $3”。超过任一上限先问用户。
- 只有确实换了场景、人物和口播才算不同版本。不要声称能保证平台判定不重复，也不要把它当成规避平台检测的手段。
- 人物参考图要有使用权，不用真实名人或未授权的人物形象。
- Agent 听不到声音，每个版本的发音和口型都需要用户抽查。
