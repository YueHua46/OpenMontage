# 沉淀方法，按方法卡批量出片

用途：一条片子验收通过后，把“怎么做出这种效果”和“怎么验收”沉淀成方法卡（playbook）。之后来了新产品或新需求，Agent 按方法卡重新写分镜和提示词，用同样的模型参数和验收规则批量生成，不用从 0 到 1 重新摸索。

方法卡保存的是做法，不是一段固定的提示词：镜头用途、拍法和节奏、产品结构约束、验收规则，以及已验证有效的写法示例。模型每次生成都有随机性，复用方法能减少试错，但不能保证每条一次到位，所以每个版本仍要走验收闭环。

下文 `<S>` 指 `<SKILL>/scripts`，命令都在仓库根目录用 `<PY>` 运行。

## 1. 每个项目都走验收闭环

生成用 `batch_generate.py`，验收用 `review_shots.py`。分辨率、比例和价格都从中转配置读，任何已配置的模型都能用（例如 Grok 720p）。

**审查员就是 Agent 自己。** 脚本只负责把画面放大到看得清（密集抽帧页、局部放大条、台词识别文字），并拒绝和记录自相矛盾的结论；它不做任何程序化的画面判断，也不改动生成画面。

跨品类常见失败汇总在 `references/failure-modes.md`；所选风格的观感要求在 `references/styles/`；所选产品大类的结构与拍法要求在 `references/categories/`。写提示词和审片时一并对照。

### 1.0 带货、转化广告的默认结构

用户要“转化”“带货”“引导下单”的片子，又没给自己的结构时，按下面写，不要只罗列功能（所选风格模板另有结构时以模板为准）：

| 段落 | 约占时长 | 作用 | 例子（居家应急呼叫设备） |
|---|---|---|---|
| 钩子 | 0–3 秒 | 一个让目标人群停下来的具体场景或问题 | 老人滑倒，远处的手机够不到 |
| 痛点 | 3–10 秒 | 放大“不买会怎样”，说清现有方案为什么不够 | 普通设备只能被动看，接不到主动求助 |
| 方案 | 10–18 秒 | 产品怎么解决这个痛点，突出最独特的一个功能 | 伸手按机身上的呼叫键，家人手机响起 |
| 证明 | 18–28 秒 | 其余卖点快速带过，作为加分项 | 多角度覆盖、夜间清晰、耐用 |
| 下单引导 | 最后 3–5 秒 | 情绪落点 + 明确动作 | 家人安心通话；“Grab yours below ↓” |

痛点和方案必须是同一件事：钩子里的问题，正好由方案段的功能解决。提案时先给这张结构表，再给逐镜内容。

### 1.05 生成前：逐镜判断模型能不能做，红色镜头改拍法

现在的视频模型有明确的能力边界：有些动作无论提示词写多细，都会出慢放、横着挪步、变形或换人。只靠“生成后发现、改提示词、再抽”，往往抽到第六七次仍不可用且白白烧钱。所以**写提示词之前，先给每个镜头分级**，记进 spec 的 `feasibility`：

| 级别 | 典型内容 | 做法 |
|---|---|---|
| 绿 | 固定或轻微手持；人站着或坐着说话、小手势；慢走、朝镜头走近；商品静置，只有环境在动 | 正常生成 |
| 黄 | 一个清楚的单一动作，1 秒内完成（按键、拿起手机、摔倒、关门）；跟着人慢走的手持镜头 | 按 1.16 写，首帧带势头，必要时用尾帧锁定；样片阶段先测 |
| 红 | 跑步、急转身、对画外声音做出反应再动作；多人互动走位；商品局部精密机械运动（转动、伸缩、开合跟踪）；App/屏幕界面动态交互；镜头从一个物体穿到另一个构图、大幅推近或环绕；水流持续冲击带线缆/复杂缝隙的商品 | **保留剧情和台词，改拍法**，见下 |

红色镜头的改法（按优先级）：

1. **用真实素材：** 商品机械动作、App 操作和设备实录画面，向用户要真机录像或手机录屏，原样使用（`compose.md`）。
2. **拆成切镜：** 一个复杂动作拆成两三个绿色镜头，靠剪辑完成。例如“听到喊声转身逃跑”拆成“听到声音、身体后缩转向一侧（近景，≤ 1 秒）”加“背影已经在跑、离开画面（2 秒，首帧就是跑动中的姿势）”；“镜头从商品穿到两人”拆成“商品近景”切“两人中景”。
3. **换成模型做得好的拍法：** 跑步用远景、背影、动作已经在进行中；反应用表情近景；复杂运镜改成固定机位加切镜。
4. **换模型试这一镜**（需要用户同意），并把结果记进 `providers.md`。

改拍法不等于删剧情：剧情、台词、顺序和时长保留，只改“怎么拍”，并在提案里逐镜列出原拍法、新拍法和理由，由用户确认。**样片阶段先拿红色和黄色镜头试**，通过后再批量。

### 1.1 生成前：按类别推出每个镜头的验收规则

**先写对首帧。** 图生视频的首帧是镜头的起点，视频从它开始演：
- 平缓动作画动作开始前一刻的状态，动作过程和结束状态写在视频提示词里。
- **剧烈、突然的动作（摔倒、绊倒、碰撞、掉落）：** 首帧要带着动作的势头（已经脚下打滑、重心偏出正在前扑的一瞬），而不是动作还没开始、引发原因已消失（如拖鞋已脱在一边），更不能画成已经坐在地上的结果（否则视频无动作可演）。
- 下一镜的首帧要接上一镜的结束状态。姿态写成可见的物理事实（“臀部在地毯上，沙发坐垫空着”），不要写“坐得稳”“姿势协调”这类会把画面拉回正常坐姿的词。

对每个镜头，按下面 12 个通用类别逐一想清楚“什么必须成立”，从脚本、商品参考图和常识推出来（若命中 `references/categories/` 品类指南，将该品类的专属检查模板一并纳入）：

| 类别 | 要想清楚的问题 | 通用例子 |
|---|---|---|
| `count` | 每种商品、附件、人物、道具各几个 | 套装件数、配件与人物数量精确；不多出前景或背景多余设备 |
| `structure` | 商品外形、开孔/按键/接口、部件连接与参考图一致 | 机身轮廓、按键与传感器位置吻合；分体配件不粘连，供电线两端完整 |
| `motion` | 哪些部件能动、动多少；其余相对桌面/墙面不动 | 仅指定活动件按真实轴向运动；底座、外壳与固定附件相对支撑面静止 |
| `orientation` | 设备、屏幕、手朝哪；操作的是正确的一面 | 手机屏幕朝向操作者；手指按的是正面控件而非后盖或镜头面 |
| `viewpoint` | 画中画（手机、镜面、设备视角）是谁、从哪看到的 | 屏幕内显示的内容符合对应镜头所在位置的真实视角，不会拍到拍摄源自己 |
| `light` | 灯、指示灯、屏幕亮灭，白天还是夜晚 | 白天夜间光线与设定一致；状态灯亮灭与工作模式吻合；手机屏幕亮灭合理 |
| `text_ui` | 屏幕文字、App 界面、包装、商品印字 | 不出现乱码、角落水印或商品外壳多出的假字；UI 时间与日夜一致 |
| `people` | 身份、体型、服装一致；手、手指、肢体、表情自然 | 同一角色脸型与躯干比例一致、同一套衣服；五根手指自然 |
| `action` | 脚本动作按顺序在镜头内真实完成 | 按剧本顺序完成指定动作，速度真实不慢放 |
| `audio` | 台词、语种、音轨完整性与一致性 | ASR 完整匹配原句、无多余尾音或未授权配乐；客观异常与主观待试听项分开记录 |
| `continuity` | 跨镜头人物、场景、道具位置与剧情依赖距离是否成立 | 同一房间布局与天气色调连贯；“够不到的手机”在各镜都确实够不到 |
| `realism` | 画面观感是否符合所选风格模板（`references/styles/`） | UGC 实拍风像手机随手拍；精致广告风干净但不塑料；无摆拍僵硬或贴纸感 |

**遮挡关系（每个有人和商品同框的镜头都要查）：** 离镜头近的东西挡住远的东西。单独传入的商品参考图常被模型当贴纸盖在最上层，导致背景商品压在前景人物手臂上。商品只是背景小物件时不单独传商品图，改用已包含商品的场景参考图；必须传时，在提示词按“离镜头从近到远”列出层次（如 `From nearest to farthest: her right forearm and hand; then the end table with the small white device, partly hidden behind her forearm; then the sofa.`）。**首帧里被完全挡住的东西，视频模型不知道它存在**：人一移开会画出空桌子。之后需要露出的商品或道具，首帧必须至少露出可辨认的部分，或用尾帧锁住。审片时在重叠处加 `regions` 放大检查。

单镜头、不和其他镜头共用人物或场景时，`continuity` 可写进 `na`。有参考图时，在 `regions` 加带参考的放大：`"face": {"box": [...], "ref": "@m-person", "ref_box": [...]}`，审片时参考图同一部位会以 `REF` 标签排在最前并排对比。

规则写进 spec：全片通用的放顶层 `checks`，单镜头的放镜头 `checks`，格式 `{"id": "...", "category": "motion", "text": "..."}`。不适用的类别写进镜头的 `na` 并说明原因。`review_shots.py lint` 检查每个镜头每个类别都有规则或 `na` 理由，缺了不让往下走。

### 1.12 所有镜头的现实规律检查

本节是生成与验收的通用推导方法，不是把历史错误逐个写成禁止词。对本镜实际出现的物体和动作作以下推导，关键约束写进提示词，完整检查留在 spec 和审查记录：

1. **物体和状态：** 列出实际存在的人、物、零件、服装与界面及起止状态。无进入、退出、遮挡或明确动作时，数量、身份、拓扑结构、材质和尺度不能自行改变（刚体不伸缩换零件，裙装转身不变裤装）。
2. **连接和自由度：** 明确什么固定在什么上、由谁支撑、哪些关节可动及范围。固定是相对于安装支撑物而非画面像素（正常机位运动会产生整体视差）。软物（线缆、衣摆、水流）可随力变形，但固定端点和连接不能无故迁移，也不能把软物全规定成刚体。
3. **原因、受力和时间：** 接触或驱动发生后才响应；落脚承重、抓握释放、重力、惯性、流体碰撞与流向合理，速度与动作量匹配。不能仅凭起止姿势正确认定中间自然。
4. **空间和观察：** 检查同深度尺度、前后遮挡、碰撞与穿透；相机变化能解释投影变化，不能解释物体独立变大或瞬移。镜中、屏中和远端设备视角须有正确物理来源。
5. **完整过程和边界：** 全镜至少 6fps 检查，快速接触、转身、遮挡后重现或状态突变处加密；同时看整体与覆盖全部连接的局部，并对照相邻切镜。写具体观察时点和因果依据，不用“符合物理学”空话替代证据。
6. **开放的失败判定：** 清单外的异常同样判失败：先归因到物体持续性、连接/自由度、动力/时序、空间或观察来源，补本镜规则并排查同类镜头，修改实际输入后有限重生成。

**运动先分清参照系：** 逐镜区分 ① 外部拍摄相机、② 被拍商品及安装支撑物、③ 屏幕/镜面内的光学视角、④ 屏幕 UI 控件四层，说明各层相对谁可动、因什么而动。外部手持轻晃不能授权屏内固定视角沿路行走，也不能授权固定商品相对墙面/桌面独立晃动；画外旁白不是任何可见物体的运动驱动力。

**背景也有结构：** 车辆门窗、家具、墙体等虽不是商品，也要有连贯的面、把手/凹槽连接和遮挡关系；首帧检查不能只框人物。

### 1.15 跨镜头的人物和场景：先做参考图

只在同一个人物、场景或道具布局出现在多个镜头里时需要；每镜独立的混剪跳过本节。

1. **参考图：** spec 加 `"kind": "reference"` 的镜头（id 建议 `m-` 开头），只出图不出视频。每个反复出现的人物一张（正面半身，片中衣着发型），每个反复出现的场景一张（主视角全景，道具在剧情位置）。参考图先审（`sheet/mark --stage frames`）并经用户确认，再出分镜。商品参考图只用干净的白底或实拍图，不用带大字图标的海报。
2. **布局说明：** 剧情依赖位置或距离时（谁够得着什么、谁看得见什么），在 spec 顶层写 `"set_plan"`，提示词与 `continuity` 规则照它写。
3. **分镜首帧引用：** `refs` 用 `"@<参考镜头 id>"` 引用参考图。先 `--only` 生成参考镜头，审完再生成其余镜头。
4. **身份母版锁定脸型与体型：** 先排查现有四视图、原分镜及参考图之间是否矛盾，只留一套有效母版并记录来源。同时保持脸部特征与完整体型（肩宽、颈围、胸腰腹、四肢粗细和衣服版型）；编辑旧分镜时明确旧图仅提供场景、机位和动作起点，角色外形统一由母版提供。用等头部大小的脸部对照与完整躯干对照一起审（含坐姿、近景、夜景）。
5. **整片设定表（`world`）：** 多镜同一故事时在 spec 顶层写 `"world"`，按场景锁定地点、时间与天气（室内窗外天气与室外一致）、光线方向、色调、符合场景的人物服装（如泥泞户外不穿违和礼服/短裙，除非用户要求），以及统一的手机界面呈现方式（全录屏或全手持拍屏，不混用）。相邻镜头并排核对天气、光线与色调。

### 1.155 带货商品的物理尺度

- 在项目 spec 记录真实尺寸来源、单位和测量范围（裸机/含配件/含底座），区分可核实真机数值与场景设定值，不编造厘米值，不用生成图反向覆盖用户真机资料。
- 按商品真实使用工况安排放置/安装位置与人物、家具、门框、手部等尺度参照；**不要把小件商品放在镜头最前景占半幅画面与远处人物同框**（会显得商品比人还大），需要看清细节时单独拍近景特写。特定品类的安装高度与比例规范见 `references/categories/`。
- 审查时分清画幅占比与物理大小：推近或裁切会同步放大同深度的商品与安装支撑面；用同深度接触面/参照物比对首帧、视频过程及切镜两侧，原分镜首帧失真时同样先重出首帧再出视频。

### 1.16 视频提示词：让动作像真的

视频模型默认把动作做得慢、平、稳，并把多步动作平均摊满整段时长。写视频提示词时按下面检查：

1. **一段只演一个动作。** 不要把五步动作塞进 4 秒。
2. **片长贴近动作真实时长。** 动作本身多长，片长就接近多长，最多加 1–2 秒动作后的状态（摔倒、按键类 2–3 秒）。
3. **写清发生时刻与真实速度。** 如 `within the first second`、`sudden`、`real-time speed, not slow motion`，剩余时间写动作后的状态。
4. **用物理因果写，不用结果词。** 先写原因（脚尖勾到地毯边），再写受力（惯性前带），最后写落点和姿势，不写 `falls naturally`。
5. **不用软化词。** 禁用 `gently`、`slowly`、`sinks down`、`safely`、`carefully`、`no impact`、`not hurt`；安全约束只写最低限度（不出现血和伤口）。
6. **写身体反应，不写表演形容词。** 写“愣住、喘气、手撑地”，不写 `dramatic`、`emotional`、`shocked expression`。
7. **合理用首尾帧锁关键动作。** 首帧带势头，尾帧锁同机位结束位置（精细动作写明“只碰 X，不碰 Y”）。尾帧必须基于首帧编辑并并排核对机位一致；保不住同机位时不用尾帧，改为让首帧直接处在落点附近。
8. **写清重力。** 掉落物写 `falls to the floor at once`，防止空中悬停。
9. **商品镜头少运镜。** 默认写 `fixed camera` 或 `slight handheld sway`，避免推近或环绕导致商品结构重绘变形。
10. **只用模型擅长的运镜。** 能做：固定机位、轻微手持、慢走跟拍、极慢小幅推近。做不像的穿越运镜、大幅推拉环绕一律拆成两镜硬切。
11. **定轴旋转视角与画中画另算。** 固定光心旋转（如云台视角）近处与远处同步平移、无步行视差，模型极难直出，优先用真机录屏；确需生成时先出更宽的固定机位画面，后期做匀速平移裁切或目标追踪裁切，UI 框线在合成层叠加（智能监控与 `app_feed.py` 细则见 `references/categories/security-camera.md`）。
12. **画外声音引发的反应拆镜拍。** “听到声音 → 转头 → 逃跑”拆成 ≤ 1 秒反应近景 + 已经在运动中的下一镜（见 1.05）。

### 1.17 风格模板与品类指南

- **风格模板（`references/styles/`）：** 管画面观感与节奏，提案选定后写进 spec 顶层 `"style"`，`realism` 规则按它写；验收通过的新风格可按 `styles/README.md` 新增。
- **品类指南（`references/categories/`）：** 管特定商品大类的结构红线、尺度与功能拍法，命中时写进 spec 顶层 `"category"`，专属检查项合入 `checks`；验收通过的新品类可按 `categories/README.md` 新增。

### 1.2 闭环步骤

1. `batch_generate.py --stage frames` 出首帧。有参考图时先 `--only` 参考镜头，审过再出其余镜头（1.15）。
2. **首帧闸门：** `review_shots.py sheet --stage frames`，查看 `frame.jpg`（长边 1280 JPEG）和放大区域，按 1.3 `mark --stage frames`。不通过的首帧用 `retake <镜头> --new-frame --frame-prompt-file 新首帧提示词.txt --reason "..."`，再 `batch_generate.py --stage frames --only <镜头...>`。未过审首帧会自动跳过视频生成。跳过首帧审核（`--skip-frame-review`）须经用户同意。
3. `batch_generate.py --stage videos` 出视频。
4. `review_shots.py sheet [--lang es]`：默认每秒 6 帧抽成大图页，每个 `regions` 逐帧裁出放大条，装有 faster-whisper 时附上台词转写。快速状态变化处按需加密。
5. 按 1.3 审查并 `mark`。
6. 不通过的镜头：按 `SKILL.md`“默认修复路径”排查（先看是否首帧就有错），改提示词或首帧，执行 `review_shots.py retake <镜头> --reason "偏差和改法" --prompt-file 新提示词.txt [--new-frame --frame-prompt-file 新首帧提示词.txt]`，多个镜头一起 `retake` 后用一次 `batch_generate.py --only a b c` 并发重生成（自动存为 `-take2.mp4` 等，旧版保留，不手动改名挪文件）。
7. 次数用完脚本拒绝重生成时，标为“未通过/待人工验收”，说明偏差与已试方案交用户决定。
8. `review_shots.py status` 查看各镜结论与选用版本，`edit.json` 的 `clip` 直接填这里列出的版本名（如 `a2-take2`）。

### 1.3 审查方法（防止只看清单、防止自相矛盾）

**静态抽帧页不等于连续播放：** 只有图片工具时如实记录为连续抽帧推断，不声称看过正常速度播放。排查来回缩放、周期抖动、机位漂移时，沿时间跟踪物体相对支撑面和背景的位置/尺度，可用只读轨迹工具 `motion_audit.py` 辅助定位可疑时段；放大长条过小看不清时加 `--region-pages` 分页。相邻镜头以相同显示尺度对比清晰度，区分源片失焦、运动模糊与编码损失。用户指出验收漏项时，立即撤销受影响的通过结论、归档旧记录并更新报告。

1. **先看全，后对照（`--observed`）：** 先不看规则，看完每页和每条放大图，客观写下物体数量、什么在何时动了、设备与屏幕朝向、屏内内容与视角、手部、文字、灯光。
   - **动作看力度与量化速度：** 量人物像素身高与每秒位移——正常步行约 0.7–1 个身高/秒（每秒约 2 步），慢跑约 1.5–2 个身高/秒，奔跑 ≥ 2.5 个身高/秒（每秒约 3 步）。写“跑”却低于 1.5 个身高/秒或原地碎步，即判慢放不通过；转身先转头上身再蹬地转胯，双腿交叉横挪或脚底打滑即判不通过。
2. **再逐条回答规则：** 每条归入 `--ok` 或 `--failed`（`--ok rest` 表示其余成立）。
3. **清单外异常照样挂掉并补规则：** 任何物理荒谬、与参考图矛盾处均判不通过，用 `--new-check 类别:描述`（或 `--new-check-global`）写回 spec，后续沉淀进方法卡。
4. **看不清就不判通过：** 加 `regions` 重出放大图仍分辨不清时，如实记录并判不通过或交用户确认。
5. **结论与记录严禁自相矛盾：** 判通过不能带失败项；台词识别相似度 < 0.9 判通过必须加 `--flag-note` 说明，脚本会拦截矛盾结论。

## 2. 把验收过的项目沉淀成方法卡

1. `playbook.py save --project <id> --spec shots.json --name <方法名>`，生成 `playbooks/<方法名>.json` 草稿（通过镜头带实际提示词与参考图作示例；未通过镜头标 `unresolved` 仅记教训）。
2. Agent 根据验收记录和用户反馈填写草稿里的 `TODO`（拍法节奏、结构、商品规则、提示词组织方式、未解决教训），不编造。
3. 发要点给用户确认后，运行 `playbook.py check --playbook playbooks/<方法名>.json`，无 `TODO` 且有验收规则即标为 `ready`。`playbooks/` 默认不入 git，由用户决定分享方式。

## 3. 用方法卡做新的片子

用户说“按上次那条做”“复用某条片子的做法”时，先运行 `playbook.py list` 找对应方法卡，找不到就问用户，不凭记忆重写。

1. 读方法卡的 `method`、`model_notes` 和未解决教训，结合新需求（新商品、新场景、新人物、新台词）及对应品类指南写新的 `shots.json`（沿用 `purpose`，重写具体商品描述）。
2. `playbook.py apply --playbook playbooks/<方法名>.json --project <新id> --spec shots.json` 补齐模型参数与规则，重点检查提示出的“新镜头类型”。
3. 照第 1 节走 `--dry-run` 报价确认 → 首帧 → 视频 → 验收 → 有限重生成 → 按 `references/compose.md` 合成。

### 3.1 一次出多条：所有条目同步推进

批量需求一开始就全部并发推进，每条独立计费与验收，在统一审核点一起停下确认：
1. **提案：** 汇总所有条目的镜头表、变量差异、高风险镜头与总报价（`batch_generate.py --project v1 v2 v3 --stage frames --dry-run`），按条和按批次一起获批预算。
2. **首帧与视频：** `--project v1 v2 v3` 一次并发提交首帧，审完再并发提交过审视频；多条出现同一共性缺陷时先统一改根因再并发 `--only` 重生成。
3. **试听与合成：** 默认各条试听版一起交用户确认后合成；用户已明确委托自主审片和合成时，按 `SKILL.md` 的委托边界执行。

## 只换变量的简单裂变

故事、卖点和镜头完全不变，只换场景、人物或口播时，写 `master.json`，运行 `plan_variants.py --master master.json` 预览版本表与报价，确认后加 `--create` 生成各项目 spec，随后照第 1 节走验收闭环。

## 注意事项

- 多条片子用一次 `batch_generate.py --project ...` 统一跑，不开多进程；渠道返回 busy 时在模型配置设 `limits.max_concurrent`（见 `references/providers.md`）。
- 只有确实更换了场景、人物和口播才算不同版本，不声称能保证平台去重判定。
- 人物参考图须有合法授权，不用真实名人或未授权形象。
- **音频核查与人工试听边界：** Agent 必须先完成 ASR 文字比对、词级切点核查与 `qc_media.py` / `voice_check.py` 声学检查，并说明台词转写一致不等于主观听感自然；未获用户“声音意见后置反馈”委托时请用户试听确认发音与口型，已获委托时如实记录待试听项而不卡停流程。
