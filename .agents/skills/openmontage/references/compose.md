# 分镜、声音与合成

## 把脚本拆成镜头

- 按 Seedance 等多镜头模型写的脚本，在 H3 上逐镜头生成。H3 单次一个连续镜头，请求最短 4 秒，短镜头生成后再裁短。
- 先按台词算时长，不要只看脚本时间。西语约每秒 2.5–3 个词，放不下时提前告诉用户总时长会变长，不切断台词。
- App 界面默认不用 HTML 手工重做，容易露馅，也容易和真实 App 不一致。优先级：① 用户提供的真实 App 录屏或截图，原样使用；② 没有真实素材时，提案阶段先向用户要；③ 用户不提供时，人物镜头让手机背面朝向观众，不展示屏幕，并说明脚本里哪些画面因此拍不到。
- 让模型生成手机屏幕容易出现乱码，只有用户接受这个风险时才做。手工重做界面只在用户明确要求时才做。
- 用户给的截图如果本身是 AI 生成、有错字或水印，要在提案里指出，请用户换真实素材，不要自行改字或重画。

## 首帧提示词（实测）

- 每个镜头写清人物服装和产品结构。产品要点逐项写，并写明不要多余部件。
- 参考图的内容会被照搬：把带人物的场景图当地点参考时，模型可能复制人物和构图。需要无人画面时不要传这类图，改用文生图；需要近景时不要传全身奔跑的画面。
- 想让人物面向观众时写明 `face clearly visible, never from behind`，只写“看着摄像头”可能得到背影。
- 出图后逐张看。尺寸不是 9:16 时保留原图，经用户同意后再裁切（`gpt-image-2` 实测返回过 1024×1536 和 1458×1536）。

## 视频提示词（实测）

- 开头写 `Starting exactly from the supplied first frame, one continuous take with no cuts.`，动作必须和首帧构图一致。
- 对白写成引号内原文，并写语言、口音和说话人。只说一个人时写 `Only the man speaks`，结尾写 `no music, no narrator, no subtitles`。
- 缩写和数字按读音写：`IP65` 写 `I P sesenta y cinco`，`100%` 写 `cien por ciento`。
- 画外音写 `off-screen`。水声等强环境声可能盖住人声，这类镜头要提醒用户重点试听。
- 2026-11-06 实测：H3 能按提示词生成西语对白和口型动作，但发音与声音一致性要用户试听。4 秒约能放 10 个西语词，更长的台词用 6 秒。
- 只转动摄像头下半部分这类局部运动，模型可能整体旋转，提案时说明可能要重做。

## 剪辑

1. 用 `qc_media.py` 的 `sound_windows` 定入点和出点，再看抽帧确认动作。
2. 写 `edit.json`，格式见 `scripts/assemble.py` 开头。
3. 一句台词要跨过切镜时，让人物在一段视频里说完整句，用 `audio_out` 让声音继续播放，画面切到 `insert`。
4. 人物声音通过设备喇叭传出时，用 `extra_audio` 的 `"effect": "speaker"`。
5. 跳切、删除停顿、改变台词顺序属于改动，要告诉用户。
6. 旁白是单独的音频文件时，写进 `edit.json` 的 `voiceover`（`at` 填镜头的 `label`，`offset` 是相对这个镜头的秒数，`tempo` 最多约 1.06）。模型原声用 `"clip_audio": false` 全部静音，或者在单个镜头写 `"mute": true`。先按旁白时长分配镜头时长，再把关键词对上关键画面。
7. 不是 9:16 的镜头（例如监控画面）写 `"fit": "contain"`，会完整放进画面、上下或左右补黑边；默认的裁满会把它裁坏。
8. 用户决定只用某段的一部分时（`review_shots.py accept --use 0-1.6`），剪辑的 `in`/`out` 照这个范围填。

## 界面和文字层

`assemble.py` 只负责视频、音频和页面骨架。这条片子独有的箭头、标注等放进 `overlay.html` 和 `overlay.js`，时间用 `{{<id>.start}}`、`{{<id>.duration}}`、`{{<id>.start+0.5}}` 这类占位符。

- 真实 App 录屏或截图放进 `hyperframes/assets/`，在 `overlay.html` 里用全屏 `<video>` 或 `<img>` 放到对应 `insert` 的时段，不要改动内容。
- 文字放在安全区内：上方约 240px、下方约 480–660px、左右约 120px 少放重要内容。
- 不要加用户没要求的字幕、卖点或功能文字。

## 渲染

```bash
<PY> <SKILL>/scripts/render.py --project <id>
```

它先运行 `hyperframes_compose` 的 `check`，再用 `render_existing` 输出 `renders/final.mp4`。加 `--check-only` 只做检查。

渲染可能要几分钟，放后台运行。`timeline_track_too_dense`、`nested_structure_needs_subcomposition` 是结构建议，错误数为 0 时可以继续。

验收目标：1080×1920，时长符合预期，解码错误为 0，响度约 -15.5 LUFS，峰值不高于 -1.5 dBFS，抽帧覆盖每个插入界面和结尾。768P 原片为 768×1344，放大到 1080×1920 时左右各裁约 8 像素，这属于输出缩放。
