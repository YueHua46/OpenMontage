# 常见失败模式：让画面不像 AI

本文件汇总跨品类通用的高频生成、审片、合成与流程故障。特定产品大类的结构、视角与专用界面故障见 `references/categories/`（如安防监控见 `security-camera.md`）；特定画面观感要求见 `references/styles/`。

**使用原则：**
1. 本表不是穷尽清单。通用审查依据是 `references/batch.md` 1.12：主动检查所有可见物体的持续性、连接与自由度、动作因果与时序、空间遮挡与观察来源。
2. **写首帧和视频提示词前通读对照；审每张首帧、每段视频时按“审片怎么发现”逐条核查，清单外违反常理的情况同样判不通过。**
3. 新增问题先归因并排查同类镜头，再提炼成无项目代号、无 `take` 流水账的通用条目补入对应表格（只属于某风格或某品类的补入对应 `styles/` 或 `categories/` 文件），不能只给单个物体加一句禁用词了事。

## 一、首帧图像

| 症状 | 原因 | 生成前怎么预防 | 审片怎么发现 |
|---|---|---|---|
| 商品像 P 上去的贴纸：光线与房间不一致、无接触阴影、边缘过锐 | 单独传入的棚拍/渲染商品图被图像模型原样贴在画面表层 | 商品只是背景小件时不单独传白底图，改用已含商品的场景参考图；必须传时写明受光方向、接触阴影和环境反光；优先向用户要真机环境实拍照 | `regions` 放大商品边缘与底部，核对光向、阴影、色温是否融入环境 |
| 遮挡反了：背景商品压在前景人物手臂上 | 贴入的商品图层被模型放在最顶层 | 按“离镜头从近到远”显式列出遮挡层次；构图尽量避开人与商品不必要的半遮挡 | 在人与商品交叠处加 `regions` 放大检查 |
| 商品在视频里凭空“消失” | 首帧里商品被人物完全挡死，视频模型不知道其存在，人移开后画出空桌面 | 后续动作会露出的商品或关键道具，首帧必须至少露出可辨认部分，或用同机位尾帧锁住 | 审首帧时预判视频里人物往哪动、移开后原本该露出什么 |
| 同一角色跨镜换脸、年龄或发型变了 | 各镜头各自从文字生成人物，或重做某张图后参考链断裂 | 先生成并确认人物参考母版（`batch.md` 1.15），所有出镜镜头用 `@id` 引用当前母版 | `regions` 加带 `REF` 标签的等头高脸部并排对比 |
| 衣帽相同但人物忽胖忽瘦，近景、坐姿、夜景像换了演员 | 原分镜与参考图矛盾；编辑时只换脸保留了旧图躯干；仅凭衣服颜色认人 | 每个角色只留一套有效脸部+完整躯干母版；明确旧分镜仅提供场景与动作起点，肩宽、颈围、胸腰腹、四肢粗细和衣型统一跟母版；连用户原分镜首帧也先核对 | 将全片出镜首帧的脸与完整躯干并排对比，不把明显肥瘦变化归咎于透视或坐姿 |
| 同一商品跨镜相对同一安装面/家具忽大忽小 | 未锁定实测尺寸测量范围；混淆画幅占比与物理大小；照搬了失真的原始分镜 | 按 `batch.md` 1.155 在 spec 锁定实测尺寸与同深度参照物；不把商品怼在最前景与远处人同框；失真原首帧整体重出 | 对比同一深度处商品与立柱/底座/门框/手部的比例（正常变焦会同步放大同深度参照） |
| 剧情依赖的距离不成立（如“够不到的手机”就在手边） | 未固定空间布局，各镜头家具与道具位置随机漂移 | spec 顶层写 `set_plan` 锁定相对位置和距离，提示词照写 | 加专属 `continuity` 规则核查该关键距离 |
| 姿势像摆拍或刻意演戏（“滑倒”像弓步、“坐地上”像坐沙发） | 逐条规定关节角度；用了“坐得稳”“姿势协调”等词；写了结果而非物理事实 | 写可见的物理事实（如“臀部跌在地毯上，沙发坐垫空着”）与本能反应 | 当成刷到的短视频看第一眼，问“这是真摔还是在摆拍” |
| 首帧选错时刻：动作未开始，或起因已消失（如拖鞋已脱在一旁） | 未按“视频从这一帧开始往后演”构思起点 | 平缓动作取开始前一刻；剧烈突然动作取刚脚下打滑、重心偏出的一瞬（`batch.md` 1.1） | 审首帧问一句：从这一刻往后，模型能自然演出目标动作吗 |
| 精细动作首帧太晚（手指已经按在键上） | 图像模型倾向于直接把动作画完 | 写明起始距离（如“手指离按键约 10 厘米，刚从桌沿抬起”） | 放大手部与目标按键的距离 |
| 情绪/喊话镜头演成夸张小品（从沙发跳起半蹲大吼） | 只写“大喊/震惊”，模型取最戏剧化的夸张姿势 | 写成克制的真人反应（如坐沙发边沿略前倾、下巴收紧、皱眉）并锁死景别 | 问一句：普通人在家遇到这事会摆这个姿势吗 |
| 近景要求出成了全身远景 | 只写 `medium close shot`，模型仍默认画全身 | 写成可度量的取景边界（如 `framed from mid-chest up, camera about 1 meter away`） | 审首帧先核对景别与分镜设计是否一致 |
| 整体像图库照片或样板间 | 均匀柔光、房间一尘不染、居中构图；用了 `realistic`、`cinematic`、`8K` 或堆砌十几个禁止项 | 按所选 `styles/` 模板写（约 150 词，核心禁止项 ≤ 3 条） | 第一眼像商业棚拍或 AI 渲染图即判 `realism` 不通过 |
| 室内窗外晴天、室外却是阴天，或人物服装与场景违和 | 未建整片设定表，室内参考图漏写窗外天气 | spec 顶层建 `world` 设定表统一锁天气、时间、光向、色调及符合场景的服装 | 相邻镜头首帧并排核对室内外天气、色调与衣着合理性 |
| 背景车辆门板、窗框、家具出现多重把手或结构错乱 | 审首帧时只框了人物，忽略了背景物体的面与连接拓扑 | 首帧全局观察同步检查背景大件（车门、门窗、桌椅）的连接合理性 | 先看全图连接关系，区分正常凹槽与多长出来的错位部件，有错先修首帧 |
| 输出尺寸不是 9:16（变成 3:4 或近方形） | 部分中转图像模型跟随参考图比例而忽略目标宽高比 | 参考图尽量统一为 9:16；留意 `batch_generate` 尺寸告警 | 比例不对先停下别出视频（图生视频会继承首帧比例）；经用户同意再裁切或用 `fit: contain` |
| 画面四角带模型水印（四角星等） | 上游底层模型自带角标水印 | 无法靠提示词彻底预防 | 每张首帧放大看四个角，有水印直接判不通过重抽，严禁修图涂抹 |
| 空景或纯商品图里多出不该有的人 | 只写了模糊的 `nobody` | 写明 `completely empty: no people and no pets anywhere` | 清点画面人数 |

## 二、视频动作与跨帧连续性

| 症状 | 原因 | 生成前怎么预防 | 审片怎么发现 |
|---|---|---|---|
| 剧烈动作演成受控慢放（绊倒变慢慢坐下，奔跑变原地碎步） | 一段塞入多步动作被平摊；用了 `gently`、`sinks down`、`no impact`、`not hurt` 软化词；首帧无势头 | 按 `batch.md` 1.16：一镜一动作，时长贴近真实耗时，写明 `within the first second, real-time speed, not slow motion` 与物理因果，禁用软化词 | 动作时段 ≥ 6fps 逐帧看，按像素身高核算每秒位移（跑步须 ≥ 1.5–2.5 个身高/秒，转身脚不横向交叉滑步） |
| 抛出或掉落的物体在空中悬停 | 模型缺乏默认重力约束 | 明确写 `falls to the floor at once` | 逐帧跟踪脱手物体的下落轨迹 |
| 精细操作碰错部位（按到机身其他面而非指定按键） | 模型分不清商品各部件功能位置 | 写明“只碰 X，不碰 Y”；必要时用同机位尾帧锁住手指落点 | 放大手部与商品接触点逐帧核对 |
| 镜头推近或环绕时商品变形（多出孔洞、图标消失、轮廓扭曲） | 运镜触发模型重绘商品细节 | 商品镜头锁死 `fixed camera` 或 `slight handheld sway`，不推近不环绕；穿越运镜拆成两镜硬切 | 逐帧放大商品与参考图比对结构稳定性 |
| 首尾帧之间画面硬扭 | 尾帧图像编辑未能保持与首帧完全相同的机位构图 | 尾帧基于首帧编辑并并排核对机位；保不住机位就弃用尾帧，改让首帧直接处在落点附近 | 出视频前先将首帧与尾帧并排比对透视和背景边缘 |
| 特写推近到一半又倒退回原位 | 把首帧原样复制兼作了尾帧（相同首尾帧是“返回起点”约束，不是外观锁） | 严禁无依据使用相同首尾帧；需推进时提供符合终点构图的真实尾帧或单首帧固定近景 | 检查全程尺度变化曲线与末段运动方向，不只看首尾两帧 |
| 不同首尾帧都对，但中间大幅超调回摆，或人物走出画面又跳回起点重走 | 模型未单调执行路径，出现中间态发散或循环动作 | 提示词写清单一路径、方向与完成时刻；仍超调时停止同方案盲抽并报告能力边界 | 检查终点前的最大偏移、方向反转及人物是否重复入画 |
| 动作结束位置与下一镜开头接不上 | 未约束本镜终点姿态与位置 | 首帧设在落点附近，或用同机位尾帧锁定结束状态 | 把相邻两镜交界帧并排比对位置与姿态 |
| 人物转身时服装拓扑突变（如短裙背面变成两条裤腿） | 模型补全不可见背面时擅自改变衣物结构 | 提示词写明具体衣物结构（如连续环形裙摆、正反侧面一致、无裤腿裤缝），配合人物四视图核对 | 转身全程 6fps 放大腰至膝盖（尤其侧背面），变形即判不通过重抽 |
| 手机后盖被当触屏按、转腕时镜头组变形，或拿错一端凑近嘴边 | 未区分后盖支撑指与前屏操作指，未约束刚体持续结构 | 写清前屏操作指与后盖支撑指、正确操作顺序（如前屏按住→底部麦克风近嘴→松开），声明手机全程保持同一刚体；或改拍屏幕特写+表情近景 | 6fps 放大手与手机（接触与转腕处加密），核对正反面、两端与镜头组；前屏不可见时不谎称看清屏幕按键 |
| 原片凭空冒出大红箭头或购物车贴图，且朝向错乱 | 否定句写“不要画箭头”反而激活了营销贴图概念，或口播词诱发图形 | 视觉提示词只描述现场实物与自然手势，不提箭头/贴图词汇；指示图形留到后期合成层添加 | 检查完整时段与画面四周留白，出现原生贴图立即判 `text_ui` 失败重抽 |
| 远景人物原地踏步（腿在迈步，几秒内位置和大小不变） | 只写“继续往前走”，缺少画面跨度与步频约束 | 写明几秒内从哪走到哪、横穿画面几分之几、每秒约几步且不停顿 | 对比首尾帧人物坐标与像素高度 |
| 受惊后退反应演成了朝镜头走近 | `steps back` 被模型泛化为普通走动 | 写明身体猛缩、向远离镜头方向后撤一步并转向出口，加 `never moves toward the camera`；拆成 ≤ 1 秒短镜 | 核对首尾帧人物画幅：变大即是在朝镜头走近 |
| 虚焦远景推近景时人物换脸/变衣领，或纯商品画外音镜头凭空长出陌生人 | 渠道未传入独立角色多图参考（仅发了模糊首帧）；无人特写误套用了人物模板 | 核实渠道真实支持的参考模式，远推近先备好清晰合规尾帧；纯商品/环境镜头用独立提示词写死空无一人、`off-screen` 画外音 | 6fps 核查全程身份与人数；系统性漂移时立即挂起 `production_hold.active=true` 修正输入 |
| 无运动指令的固定商品或部件出现残余微动/随声晃动 | 提示词放开了可动部件，或随机生成漂移；静音并不能证明或消除画面微动 | 无动作指令的镜头写死整机及附件全部静止；不靠静音测试猜因果，改用首尾帧或更换有效输入约束 | 全程同尺度对比固定部件相对背景边缘的位置 |
| 同一镜头改提示词连抽六七次仍不过，预算翻倍 | 把模型能力边界问题（红色镜头）当成了提示词措辞问题 | 同一镜头同一模型能力原因失败 2 次即停抽，按 `batch.md` 1.05 改拍法、换真机素材或经用户同意换模型（记入 `providers.md`） | 复盘 `review.json` 历史重抽次数与失败原因 |

## 三、审片过程本身的误判

| 症状 | 原因 | 怎么避免 |
|---|---|---|
| 明显失真的画面被判成通过 | 只机械核对规则列表和事件先后顺序，没做观众第一眼直觉判断 | 严格按 `batch.md` 1.3：先不看规则写 `--observed` 客观观察，再问“正常速度刷到第一眼哪里假”，清单外异常照样判挂并 `--new-check` |
| 慢慢坐下被误判成真摔倒 | 抽帧过稀（几秒只抽寥寥几张） | 全镜抽帧不低于每秒 6 帧，快速接触/摔倒时段加密；脚本低于默认帧率会告警 |
| 遮挡反转、手指错位或小部件变形漏检 | 只看整幅缩略图，或放大长条缩得太小未看清就默认通过 | 重叠处、商品、手、脸必加 `regions`；长条过小看不清时用 `sheet --region-pages` 分页，看不清绝不判通过 |
| 对话直接报 `413 Payload Too Large` 中断 | 直接打开了 2–3 MB 的原始 PNG 抽帧，base64 在历史里不断重发 | 严格遵守 `SKILL.md`“看图”：只看 `sheet` 或 `preview.py` 产出的长边 ≤ 1280 JPEG，单轮看图 ≤ 6 张 |
| 缩略图并排看产生视错觉，或自写跳帧解码取错帧，误判稳定商品在“周期抖动”白白重抽 | 人眼看并排小格易把构图差看成位移；`CAP_PROP_POS_FRAMES` 随机跳帧不准 | 统一用 `review_shots.py sheet` 或顺序解码；怀疑微抖动时用 `motion_audit.py` / `cv2.phaseCorrelate` 测像素位移（< 1px 即稳定） |
| 角色大喊/惊呼镜头被 `voice_check.py` 误判为“换了人” | 同一人大喊时基频音高本来就会升至平静说话的 1.6–2 倍 | 情绪高亢台词单独核算：平静男声约 130 Hz 喊到 200–260 Hz 属正常生理范围，超过约 2.3 倍再判换人，同时结合 ASR 完整性判断 |
| 仅凭小图模糊印象把正常纹理写死为故障，或仅凭轨迹数值平稳就放过语义错误 | 未回查相邻时间点的高清局部，混淆辅助指标与视觉事实 | 有疑点先按相同显示尺度回查相邻帧原片局部；轨迹诊断仅作只读定位，新证据不支持旧结论时及时纠正，不盲目重抽也不草率放行 |
| 相邻镜头切换时画面突然发糊软化，但技术解码检查全绿 | 混用了不同分辨率/锐度的模型旧素材，仅用分辨率和码率代替观感验收 | 相邻同场景镜头以相同显示尺度并排对比静止结构与衣料纹理，区分源片软化与合成编码损失 |

## 四、剪辑与合成

| 症状 | 原因与预防 |
|---|---|
| 旁白比画面长，口播与关键动作错位 | 先按语速算台词时长（英文约 2.5–2.8 词/秒，西语约 2.5–3 词/秒）再定镜头长度；需要时吃满源片时长、压缩停顿，旁白 `atempo` 加速不超过约 6%，确保关键词压中动作瞬间 |
| 非 9:16 镜头被裁掉关键内容 | 宽屏或特殊比例素材在 `edit.json` 设 `"fit": "contain"` 完整放入并留黑边，不使用默认裁满 |
| 切镜处闪现单帧黑场，但四位小数秒数看似首尾相接 | 浮点秒数四舍五入造成帧缝隙。必须用**整数帧**累计入出点与时长后再除以输出 fps；对成片跑单帧灵敏度的全黑检测，发现后修时间轴，严禁补帧冻结原片 |
| 旁白每句像换人，或切分时把句中逗号停顿切到了下一段 | 锁死唯一 `voice.reference_id` 整段一次生成；用 `split_narration.py`（优先 faster-whisper 词级时间戳）切分，逐段核对打印的首尾词并跑 `voice_check.py` |
| 单镜 ASR 看似正常，合成成片后才暴露某镜尾部多出模型胡乱生成的语音 | 单镜检查不能替代整片检查。渲染出 `final.mp4` 后必须再跑一次完整 ASR；发现多余尾音时按词时间戳在正常剪辑里裁掉尾段并重验成片 |
| 结尾旁白念完后还拖着 2–3 秒无声画面 | 最后一句结束后 CTA 按钮停留 1.5–2 秒即收尾，裁短末镜；用 `qc_media.py` 的 `sound_windows` 确认结尾静音 ≤ 2 秒 |
| 成片响度偏低（如 −17 LUFS）或 AAC 编码后真峰值超标 | 用 `assemble.py` 测整轨响度自动增益并限幅在 −2 dBFS 左右；渲染后必跑 `qc_media.py` 确认响度约 −15.5 LUFS、峰值 ≤ −1.5 dBFS |
| 混入无音轨的纯画面合成片段时 ffmpeg 报错无流 | 走标准 `assemble.py`（已自动为无音轨片段补静音轨），不手拼裸 ffmpeg 滤镜链 |
| 字幕对比度不够，或文字/CTA 按钮挡住人脸与商品 | 小字加半透明深色底并置于安全区内；按各镜首帧留白排字（末镜首帧提前预留按钮空位），成片每镜抽中间帧复核遮挡 |
| 画面出现多余 AI 披露小字，或未核实卖点被擅自删改 | 默认不加画面披露小字（提醒用户开平台 AI 标签）；存疑卖点在提案逐条列风险交用户拍板 |
| 修复局部缺陷后，交付成片总时长明显短于提案承诺范围 | 提案明确记录原稿参考长、目标成片时长区间与素材总长，将目标时长列为独立验收项；剪掉废尾后若总长不足，按预算补齐合理镜头，严禁靠慢放、循环或硬停凑时长 |

## 五、渠道、账本与流程管理

| 症状 | 原因与处理规范 |
|---|---|
| 用户让“优化画面物理真实性”，结果把 20 镜长剧本砍成了 10 镜短片 | 混淆了“缺陷修复”与“剧本改编”。修缺陷前先锁死原稿逐镜顺序、全部台词与目标总时长，只允许在保持原剧情信息的前提下改拍法或拆切镜 |
| 查询任务状态时遇 `HTTP 403 insufficient balance`，误以为没提交成功而加 `--resubmit` 导致重复扣费 | 严格区分“提交前拒单（无任务 ID）”与“查询阶段报错（已有任务 ID）”。已有任务 ID 时结果与扣费未定，保留原任务与预算预留，待用户充值后用原参数恢复查询，绝不重发新请求 |
| 重做了人物/场景参考母版后，引用该母版的旧镜头仍挂着之前的“通过”结论 | 母版或共享首帧更新后，下游引用镜头的旧审查结论立即作废，必须重置为待审并独立保存新证据，且不得覆盖母版自身的审查记录 |
| 用户特批“这镜虽然有点小瑕疵但先用吧”，Agent 把审查结论改成了 `passed` | 严禁篡改客观审查结论。用 `review_shots.py accept [--use 起-止]` 记录为用户特批采用，保留原 `failed` 诊断记录备查 |
| 已经发现角色连环换脸或通道参数未生效，仍在并发跑完剩余十几个付费镜头 | 发现系统性输入失效时，立即在 spec 设 `production_hold.active=true`（`batch_generate.py` 会拦截新付费请求但允许 `dry-run`），修好输入并单镜验证通过后再解除 |
